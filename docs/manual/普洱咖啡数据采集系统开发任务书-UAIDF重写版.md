版本：G1 确认稿  
日期：2026-06-18  
适用框架：Universal AI Delivery Framework（UAIDF）  
项目基线：django-vue3-admin   
移动端：UniApp，优先 App  
Web 端：django-vue3-admin Vue3 管理端  
文档定位：人类团队确认 + Codex/AI 执行合同

## 1. 文档目的与适用对象

本文用于把“普洱咖啡数据采集系统”纳入当前 AI 通用开发框架进行开发、验证和交付。

本文同时服务两类对象：

- 项目负责人、业务方、产品、设计、开发、测试、运维：用于确认范围、阶段、职责、验收和风险。
- Codex/AI 开发代理：用于读取任务边界、阶段门禁、执行规则、提示词和证据要求。

本文不是传统一次性需求说明，而是一个可执行、可恢复、可审计的开发任务书。后续所有设计、开发、测试、联调和交付，都应以本文和 UAIDF 状态文件为准。

## 2. 项目背景与建设目标

普洱咖啡数据采集系统面向咖啡种植、采样、照片采集、设备测量、OCR 识别、质量审核、标注、统计和数据集导出场景。

系统目标是在不破坏 `django-vue3-admin` 上游能力的前提下，建设一套 App 优先、Web 管理、后端支撑、OCR 识别、真实服务可联调的完整数据采集闭环。

一期完整交付应覆盖：

- UniApp App 现场采集端。
- django-vue3-admin Django 服务端。
- django-vue3-admin Vue3 Web 管理端。
- PaddleOCR 服务。
- Provider 适配层。
- MySQL 8、Redis、Celery、Docker Compose。
- 自动测试、安全检查、真实服务配置门禁和交付文档。

### 3.2 允许的框架改造范围

本项目允许对 `django-vue3-admin` 做小范围受控改造。

允许改造：

- 权限、菜单、数据权限、字段权限的业务扩展。
- 文件上传、图片管理、对象存储适配。
- 操作日志、审计日志、Provider 调用日志扩展。
- Celery 任务、异步处理、导出任务扩展。
- 与业务强相关的基础组件扩展。

改造约束：

- 必须优先复用上游能力。
- 不得绕过上游认证、权限、菜单、日志和数据权限体系。
- 改动框架核心前必须输出 ADR。
- 高风险改造必须有回归测试和回滚说明。
- 不得为了快速开发删除核心规则、降低权限检查或跳过安全校验。

## 4. 一期完整交付范围

### 4.1 P0 必须交付

P0 是一期完整交付的核心能力。

- App/Web 共用用户、组织、角色和权限。
- 手机号 + 密码登录。
- 采集员、审核员、管理员、查看员等角色权限。
- 先编号后采集。
- `Plot_ID`、`Point_ID`、`Event_ID`、`Photo_ID` 四级主键。
- 地块、采样点、采集事件、照片资产的完整关系。
- 定位、手动选点、地块边界、面积复核。
- 分类拍照、水印、不可变原图、metadata、图片预检。
- 离线草稿、上传队列、断点续传、分片上传、幂等提交和 Manifest。
- 设备测量、异常复测、全部记录留存。
- PaddleOCR、华为 OCR、人工录入 Provider 契约。
- OCR 原始响应、置信度、人工修正、调用日志和审计。
- 图片和数据包质检。
- 退回复核。
- B 级数量规则。
- Web 业务菜单、数据列表、图片审核、OCR 校正、配置、统计、绩效和导出。
- MySQL 8、Redis、Celery Worker/Beat、PaddleOCR、健康检查和持久化 Compose。
- 自动测试、安全检查、真实服务配置门禁和交付文档。

### 4.2 P1 一期内交付但可后置

P1 必须纳入一期，但可以排在 S3 后段或 S5 前完成。

- 人工框选和标签版本。
- 统计口径中心。
- 完整数据包离线浏览索引。
- 高德、聚合天气、华为 OCR 的配置、Mock、连接测试入口。
- 腾讯/百度地图 Provider 契约、启停、配置和可替换架构。
- 更完整的绩效统计和导出筛选。

### 4.3 明确非目标

一期不承诺：

- 自动识别病虫害。
- 自动识别咖啡品种。
- 自动生成目标检测框或分割掩码。
- 腾讯/百度地图完整真实验收。
- 未获得真实设备样本时的 OCR 通用高准确率。
- 没有真实密钥、真实样本、真机环境时强行声明真实验收通过。

## 5. UAIDF 阶段与门禁

### 5.1 Stage 与 Gate

在 UAIDF 中：

- `S` 表示工作阶段。
- `G` 表示门禁确认点。

```text
S = 做事情的阶段
G = 是否允许进入下一阶段的确认点
```

本项目完整路径：

```text
S0 新基座初始化
  -> G0 立项/基线确认
S1 需求澄清与任务书确认
  -> G1 需求确认
S2 UI/UX、架构、数据库、API 和测试设计
  -> G2 设计确认
S3 App 优先开发 + 后端接口 + Web 管理端
  -> G3 实现确认
S4 本地自动验证、代码审查、发布准备
  -> G4 发布/真实联调确认
S5 真实服务、真机、真实样本联调
  -> G5 运行确认
S6 交付、复盘、框架沉淀
  -> G6 复盘确认
```

### 5.2 门禁定义

| Gate | 名称 | 主要确认内容 | 确认人 |
|---|---|---|---|
| G0 | 立项/基线确认 | 新基线、技术路线、项目开始点 | 项目负责人、技术负责人 |
| G1 | 需求确认 | P0/P1、非目标、验收标准、外部依赖 | 用户、产品、项目负责人 |
| G2 | 设计确认 | 全部 UI、架构、数据库、API、权限、测试方案 | 用户、设计、技术、测试 |
| G3 | 实现确认 | 本地功能、自动测试、代码审查、证据 | 技术负责人、测试 |
| G4 | 发布/真实联调确认 | 部署、回滚、真实配置、联调条件 | 项目负责人、运维、测试 |
| G5 | 运行确认 | 真机、真实服务、真实样本和业务验收 | 用户、测试、运维 |
| G6 | 复盘确认 | 交付结论、遗留问题、框架沉淀 | 团队负责人 |

## 6. 阶段任务

### 6.1 S0 新基座初始化

目标：建立清晰、可恢复、可审计的项目起点。

任务：

1. 锁定 `django-vue3-admin` 上游提交。
2. 建立 UAIDF 治理文件。
3. 建立 `automation/state.json`、`automation/acceptance.yaml`、`automation/runbook.md`。
4. 明确 App 优先、Web 使用 Vue3 管理端、移动端使用 UniApp。
5. 输出 S0 基线报告。

完成条件：

- 上游已锁定。
- 本地基础环境可启动，或阻塞原因清晰。
- 项目开始点明确。
- 可以进入 G0。

### 6.2 G0 立项/基线确认

确认事项：

1. 接受基于 `django-vue3-admin`。
2. 接受移动端 UniApp，优先 App。
3. 接受 Web 使用 django-vue3-admin Vue3 管理端。
4. 接受使用 UAIDF 管理阶段、门禁和证据。

G0 通过后进入 S1。

### 6.3 S1 需求澄清与任务书确认

目标：把业务想法整理成可验收、可开发、可测试的任务书。

任务：

1. 梳理用户角色和权限。
2. 梳理业务流程。
3. 拆分 P0、P1 和非目标。
4. 定义外部依赖和阻塞条件。
5. 生成 `automation/acceptance.yaml` 初版。
6. 输出 G1 需求确认稿。

完成条件：

- 每个 P0 需求都有验收标准。
- 每个外部依赖都有证据要求。
- 可以进入 G1。

### 6.4 G1 需求确认

用户确认：

1. 接受 P0/P1 范围。
2. 接受明确非目标。
3. 接受一期完整交付。
4. 接受 App 优先。
5. 接受 UI 全部由系统自动设计，确认后再开发。
6. 接受真实服务和真机可因外部条件标记 `BLOCKED`。
7. 接受验收必须基于证据。

G1 通过后进入 S2。

### 6.5 S2 UI/UX、架构、数据库、API 和测试设计

目标：先完成设计确认，再进入开发。

任务：

1. 系统自动设计 UniApp App 全部页面。
2. 系统自动设计 Web 管理端全部页面。
3. 输出页面清单、字段、按钮、状态、权限和异常流程。
4. 输出低保真原型或浏览器原型。
5. 设计领域模型、数据库模型、不可变策略和版本策略。
6. 设计 API 契约、权限矩阵、Provider 契约和错误模型。
7. 设计 OCR、图片、水印、上传、质检、导出和测试方案。

完成条件：

- `docs/ui/` 页面设计完整。
- `docs/design/` 架构和数据设计完整。
- `docs/api/` 接口契约完整。
- `automation/acceptance.yaml` 与设计一致。
- 可以进入 G2。

### 6.6 G2 设计确认

用户确认：

1. App 所有页面、字段、按钮、状态和异常流程。
2. Web 所有页面、菜单、权限、操作和配置入口。
3. 数据库、API、OCR、地图、天气、存储 Provider 契约。
4. 自动测试、人工测试和验收方式。

G2 通过前禁止开发业务代码。G2 通过后进入 S3。

### 6.7 S3 App 优先开发、后端开发、Web 开发

目标：先打通 App 现场采集闭环，再补齐后端和 Web 管理能力。

推荐顺序：

1. 后端基础模型、迁移、字典、菜单初始化。
2. 后端登录、权限、任务、地块、点位、采集、照片、OCR、质检 API。
3. UniApp App 登录、任务、采集、拍照、本地草稿、上传队列、OCR 校正、提交。
4. Web 业务菜单、采集数据、照片审核、OCR 校正、配置、统计、导出。
5. PaddleOCR 服务、设备模板和 OCR 解析。
6. Docker Compose、环境模板、安全配置。

完成条件：

- P0 主流程无占位按钮。
- App 第一条采集闭环可跑通。
- Web 核心管理页面可用。
- 后端核心 API 有自动测试。
- 可以进入 G3。

### 6.8 G3 实现确认

确认事项：

1. 本地实现是否完成。
2. 自动测试是否运行。
3. 关键人工测试是否记录证据。
4. 代码审查问题是否处理。
5. P0 是否全部为 `PASS`、`BLOCKED` 或明确的 `NOT_VERIFIED`。

G3 通过后进入 S4。

### 6.9 S4 本地自动验证与发布准备

目标：证明本地质量可靠，并准备真实联调。

任务：

1. 静态检查、单元测试、权限测试、集成测试、E2E 和安全检查。
2. 使用 Mock Provider 验证地图、天气、OCR 契约。
3. 验证图片、分片续传、Manifest、Hash、导出。
4. 输出真实服务配置清单。
5. 输出部署和回滚说明。

完成条件：

- 本地质量门禁通过。
- Mock 和真实证据分开。
- 外部阻塞清晰披露。
- 可以进入 G4。

### 6.10 G4 发布/真实联调确认

确认事项：

1. 是否具备真实 Provider 配置。
2. 是否具备 Android/iOS 真机。
3. 是否具备真实设备图片样本。
4. 是否允许进入真实联调。

G4 通过后进入 S5。

### 6.11 S5 真实服务、真机、真实样本联调

目标：证明系统在真实条件下可用。

任务：

1. 高德地图真实调用回归。
2. 聚合天气真实调用回归。
3. 华为 OCR 手动测试。
4. PaddleOCR 真实设备样本测试。
5. Android/iOS 真机测试。
6. Web/API/PaddleOCR 真实环境登录和操作验证。

完成条件：

- 真实服务证据单独记录。
- 真机证据单独记录。
- 未满足条件的项目标记为 `BLOCKED`，不能标记为 `PASS`。
- 可以进入 G5。

### 6.12 G5 运行确认

确认事项：

1. 真实服务是否可用。
2. 真机流程是否可用。
3. 用户是否接受剩余阻塞项。
4. 是否允许交付一期。

G5 通过后进入 S6。

### 6.13 S6 交付、复盘、框架沉淀

目标：完成交付并沉淀下一轮改进。

任务：

1. 输出最终交付报告。
2. 输出部署文档、运维文档、用户使用说明。
3. 输出安全检查和代码审查报告。
4. 输出复盘报告。
5. 将可复用提示词、配置、测试方法沉淀到 UAIDF。

完成条件：

- 一期交付结论明确。
- 剩余问题有负责人和计划。
- 可以进入 G6。

## 10. 验收矩阵与证据规则

验收状态只能使用：

- `PASS`
- `FAIL`
- `BLOCKED`
- `NOT_VERIFIED`

要求：

- 每个 P0/P1 需求必须在 `automation/acceptance.yaml` 中登记。
- 每个需求必须有实现位置。
- 每个需求必须有自动测试或人工测试说明。
- 每个通过项必须有证据。
- Mock 证据和真实证据必须分开。
- 不得把 `NOT_VERIFIED` 当作 `PASS`。
- 不得把 `BLOCKED` 包装成已完成。

## 11. 外部依赖 BLOCKED 规则

以下条件缺失时，允许标记为 `BLOCKED`，但必须写清解除条件：

- 缺少高德地图真实 Key。
- 缺少聚合天气真实 Key。
- 缺少华为 OCR 服务开通状态和真实配置。
- 缺少 Android/iOS 真机。
- 缺少真实设备图片样本集。
- 缺少生产或准生产部署环境。

`BLOCKED` 必须包含：

- 阻塞项。
- 影响范围。
- 当前已完成证据。
- 解除条件。
- 需要谁提供什么。
- 下一步动作。

## 12. 风险与控制

| 风险 | 控制 |
|---|---|
| 任务书没有开始点 | 明确 S0/G0/S1/G1 |
| 旧项目证据误用于新基座 | 新基座重新生成验收证据 |
| UI 未确认就开发 | G2 前只设计，不写业务代码 |
| App 现场弱网丢数据 | 本地不可变记录、幂等键、Hash、Manifest、续传测试 |
| OCR 精度不稳定 | 设备模板、置信度、人工修正、真实样本报告 |
| 地图坐标混用 | Provider 契约显式坐标系，转换与面积测试 |
| 密钥泄露 | 环境变量、加密存储、脱敏、审计、轮换说明 |
| 框架核心改造失控 | ADR、回归测试、回滚说明 |
| 大规模导出阻塞服务 | Celery 异步、进度、权限、过期清理和限额 |
