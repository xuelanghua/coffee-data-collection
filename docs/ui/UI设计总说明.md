# UI 设计总说明

## 设计目标

一期 UI 以现场采集闭环为核心：采集员在 App 中完成登录、任务查看、地块/点位选择、采集事件创建、拍照、离线草稿、上传、OCR 校正和提交；审核员在 Web 中完成数据审核、图片审核、OCR 校正、退回复核、统计和导出。

## 产品原则

- App 优先：移动端优先保证弱网、离线、低打扰和现场快速操作。
- Web 管理：Web 保持 django-vue3-admin 的管理台风格，使用菜单、表格、筛选、抽屉、弹窗和详情页组织高密度信息。
- 证据优先：任何提交、修正、审核、导出都保留原始数据、操作人、时间、版本和证据。
- 原始不可变：原图、原始采集记录、OCR 原始响应只增不改；修正以版本、修正记录或审计记录表达。

## 角色

| 角色 | App 可见性 | Web 可见性 |
|---|---|---|
| 采集员 | 任务、地块/点位、采集、草稿、上传队列、退回修改、我的记录 | 只读本人采集记录，通常不进入管理后台 |
| 审核员 | 退回任务和本人处理记录 | 采集数据、照片审核、OCR 校正、质检、退回复核 |
| 管理员 | 现场协助入口 | 全部业务菜单、配置、统计、导出、权限初始化 |
| 查看员 | 只读任务和记录 | 只读列表、详情、统计、导出受限 |

## 导航结构

App 使用底部 Tab：

- 任务
- 采集
- 上传
- 我的

Web 使用 django-vue3-admin 左侧菜单：

- 咖啡采集
- 质检审核
- OCR 与 Provider
- 统计导出
- 系统配置

## 视觉和交互基线

- App 面向户外使用，按钮高度不低于 44px，关键动作底部固定，危险动作二次确认。
- App 每个表单页顶部显示状态条：草稿、待上传、识别中、待校正、待提交、已提交、已退回。
- Web 使用 Element Plus 表格、表单、Tabs、Drawer、Dialog、Steps、Upload、Image Preview、Descriptions。
- Web 页面保留 FastCrud 习惯：筛选区、工具栏、表格、批量操作、详情抽屉。
