# 系统架构设计

## 总体架构

```text
UniApp App
  -> Django REST API (django-vue3-admin)
    -> coffee 领域模块
    -> MySQL 8
    -> Redis
    -> Celery Worker/Beat
    -> 文件/对象存储
    -> Provider 适配层
      -> 高德地图
      -> 聚合天气
      -> PaddleOCR 服务
      -> 华为 OCR
      -> 人工录入

Vue3 Web 管理端
  -> Django REST API
```

## 后端模块边界

推荐目录：`backend/apps/coffee/`。

模块：

- `models`：任务、地块、点位、采集事件、照片、测量、OCR、质检、导出、Provider 配置。
- `serializers`：DRF 输入输出契约，禁止直接透出厂商原始结构。
- `views`：App API、Web API、审核 API、导出 API。
- `services`：编号、Manifest、上传、OCR、质检、统计、导出。
- `providers`：地图、天气、OCR、存储适配器。
- `tasks`：OCR 异步、导出异步、质检异步、清理任务。
- `tests`：API 测试和领域规则测试。

## Web 模块边界

推荐目录：

- `web/src/views/coffee/`
- `web/src/api/coffee/`

使用 Element Plus、FastCrud、现有权限菜单体系。业务菜单通过 django-vue3-admin 菜单/按钮权限初始化，不绕过上游 RBAC。

## App 模块边界

推荐目录：`coffee-collector-app/`。

模块：

- 页面：登录、任务、地块、采集、拍照、OCR、上传、我的。
- 本地存储：草稿、上传队列、Manifest、离线包。
- 服务：API 客户端、上传客户端、Provider 客户端、离线同步。
- 状态：用户、任务、草稿、队列、网络。

## 数据流

1. Web 管理员创建任务、地块和点位。
2. App 同步任务和离线包。
3. App 在点位下创建采集事件并生成本地幂等键。
4. App 拍照、生成 Photo_ID、水印、metadata、Manifest。
5. App 分片上传照片和 Manifest。
6. 后端校验 Hash、幂等键、必填项，创建事件包。
7. Celery 调用 OCR Provider，记录原始响应。
8. App 或 Web 进行人工校正。
9. Web 审核、质检、退回或通过。
10. Web 发起统计和导出任务。

## 安全设计

- 复用 django-vue3-admin 认证、菜单权限、按钮权限、数据权限和操作日志。
- 外部 Key 只放环境变量或受控配置，不硬编码。
- Provider 调用日志脱敏存储。
- 原图、原始 OCR、原始采集记录只增不改。
- 导出文件设置权限、过期时间和审计日志。

## 受控框架改造

允许：

- 增加业务菜单、按钮权限、字段权限。
- 扩展文件上传、图片资产、审计日志、Provider 调用日志。
- 增加 Celery 异步任务和导出任务。

高风险改造触发 ADR：

- 修改认证流程。
- 修改核心权限判断。
- 修改菜单或数据权限底层语义。
- 修改文件存储全局行为。
