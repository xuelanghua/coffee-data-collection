# 测试方案

## 测试分层

| 层级 | 范围 | 命令/方式 |
|---|---|---|
| 领域规则 | 编号、B 级规则、状态流转、Manifest、Hash、幂等 | `PYTHONPATH=backend python3 -m unittest discover -s backend/apps/coffee/common/tests -v` |
| 后端 API | 登录、任务、地块、点位、事件、照片、OCR、质检、导出 | `cd backend && DATABASE_TYPE=SQLITE3 REDIS_ENABLE=false API_LOG_ENABLE=false .venv/bin/python manage.py test apps.coffee.tests -v 2` |
| OCR 服务 | 模板解析、预处理、错误、超时 | `PYTHONPATH=services/paddleocr python3 -m unittest discover -s services/paddleocr/tests -v` |
| Web | lint、build、菜单和页面人工检查 | `cd web && npm run lint && npm run build` |
| App | 单测、lint、构建、弱网人工测试 | `cd coffee-collector-app && npm test && npm run lint && npm run build:app` |
| 全量 | 本地自动验证 | `scripts/verify-all.sh` |

## P0 测试重点

- 手机号密码登录和角色权限。
- 先编号后采集，四级主键唯一。
- 地块、点位、事件、照片关系。
- 分类拍照、水印、metadata、图片预检。
- 离线草稿、上传队列、分片续传、幂等提交、Manifest。
- 设备测量、异常复测、全部记录留存。
- OCR 原始响应、置信度、人工修正和调用日志。
- 质检退回、复核版本、B 级数量规则。
- Web 审核、OCR 校正、统计、绩效和导出。

## Mock 与真实证据

Mock 可 PASS：

- Mock 地图、天气、OCR Provider 契约。
- 本地 PaddleOCR 服务健康检查和样例图片。
- 本地上传、Hash、Manifest、导出任务。

真实证据必须单独记录：

- 高德地图真实 Key 调用。
- 聚合天气真实 Key 调用。
- 华为 OCR 真实配置调用。
- Android/iOS 真机。
- 真实设备图片样本集。
- 生产或准生产部署环境。

缺失时标记 `BLOCKED`，不得写 PASS。

## 人工验收脚本

App 第一条闭环：

1. 登录。
2. 同步任务。
3. 选择地块和点位。
4. 创建采集事件。
5. 分类拍照。
6. 保存草稿。
7. 上传队列完成。
8. OCR 识别。
9. 人工校正。
10. 提交。
11. Web 审核通过或退回。

Web 审核闭环：

1. 登录管理员/审核员。
2. 查看采集事件列表。
3. 打开详情。
4. 审核照片。
5. 校正 OCR。
6. 运行质检。
7. 退回或通过。
8. 查看统计。
9. 创建导出任务。
