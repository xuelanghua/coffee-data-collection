# 数据库设计

## 命名和不可变规则

- 主表使用 django-vue3-admin 基础字段：创建人、创建时间、更新人、更新时间、软删除。
- 业务主键字段使用 `Plot_ID`、`Point_ID`、`Event_ID`、`Photo_ID` 对外展示。
- 原始采集记录、原图、OCR 原始响应、Provider 调用响应只增不改。
- 修正通过版本表、修正记录或审计记录表达。

## 核心表

本设计按三层组织数据：

1. 原始资产层：保存不可变事实，包括原图、OCR 原始响应、Provider 调用日志。
2. 采集业务层：保存一条 App 最终提交的数据包和最终采用的结构化字段值。
3. 审核修正层：保存 OCR 人工纠正、质检审核、退回和复核版本。

App 端最终提交使用一个提交接口完成；图片上传和 OCR 识别在提交前独立调用。最终提交接口提交的是结构化 Manifest 和字段值引用，不直接承载大图二进制或同步阻塞 OCR 调用。

### coffee_task

字段：id、task_code、name、area_name、status、plan_start、plan_end、owner_id、description、config_version。  
关系：一对多地块、点位、采集事件。

### coffee_plot

字段：id、plot_id、task_id、name、admin_region、boundary_geojson、area_mu、area_calc_method、coordinate_system、source_type、created_in_field、collector_id、area_check_status、review_status、reviewed_by、reviewed_at、status。  
索引：task_id、plot_id 唯一。

定位：地块可以由 App 在现场地图圈选后直接创建为正式地块，并立即进入采集。Web 后台做事后复核，不阻塞现场采集。

字段说明：

- `boundary_geojson`：App 圈选的种植地块边界，多边形 Polygon。
- `area_mu`：App 按当前边界自动计算出的面积。
- `area_calc_method`：面积计算方法，如 geodesic、projected。
- `coordinate_system`：坐标系，如 gcj02、wgs84。
- `source_type`：app_drawn、web_created、imported。
- `created_in_field`：是否现场创建。
- `area_check_status`：not_checked、matched、mismatch、adjusted。
- `review_status`：pending_review、confirmed、returned、adjusted。

### coffee_plot_boundary_version

字段：id、plot_id、boundary_geojson、area_mu、area_calc_method、coordinate_system、source_type、version、created_by、created_at、review_note。  
索引：plot_id + version 唯一。  
定位：保留 App 原始圈选边界和 Web 事后调整边界。后台复核如调整边界，只新增版本，不覆盖 App 原始边界。

### coffee_point

字段：id、point_id、task_id、plot_id、longitude、latitude、altitude、coordinate_system、source_type、created_in_field、collector_id、review_status、status。  
索引：task_id + point_id 唯一。

定位：点位可以由 App 在现场地块内点选后直接作为正式采集点进入采集。Web 后台事后复核点位是否落在地块内、是否符合任务规则。

字段说明：

- `source_type`：app_selected、web_created、imported。
- `created_in_field`：是否现场创建。
- `review_status`：pending_review、confirmed、returned、adjusted。

### coffee_collection_event

字段：id、event_id、task_id、plot_id、point_id、collector_id、idempotency_key、status、collected_at、submitted_at、version、manifest_hash、location_snapshot、weather_snapshot。  
索引：event_id 唯一、idempotency_key 唯一、task/plot/point。

定位：一条 App 最终提交的数据包，也是 Web 单条详情页的聚合根。详情页以 `Event_ID` 查询后聚合展示地块、点位、图片、OCR、最终字段值、测量、质检和审计。

### coffee_photo_asset

字段：id、photo_id、event_id、category、original_file、watermarked_file、sha256、metadata_json、precheck_status、review_status、immutable_status、uploaded_at。  
索引：photo_id 唯一、event_id、category。

### coffee_measurement_record

字段：id、event_id、device_no、measured_at、wind_speed、wind_direction、air_temperature、air_humidity、atmospheric_pressure、rainfall、soil_moisture、soil_temperature、soil_salinity、soil_ph、source_photo_id、ocr_result_id、is_abnormal、retake_of_id、remark。  
规则：设备采集数据包括风速、风向、空气温度、空气湿度、大气压力、雨量、土壤湿度、土壤温度、土壤盐分、土壤 PH 值。OCR 识别结果回填这些字段，人工校准后的最终值随最终提交落库。复测记录用 `retake_of_id` 关联，不覆盖原记录。

### coffee_event_field_value

字段：id、event_id、field_code、field_label、value_text、value_number、value_json、unit、source_type、source_photo_id、ocr_result_id、ocr_raw_value、ocr_confidence、corrected_from、correction_reason、version、created_by、created_at。  
索引：event_id + field_code + version；event_id + source_type。  
定位：保存 App 当前页面输入框最终提交采用的结构化字段值。该表是统计、导出和详情页字段展示的主要来源。

字段来源：

- `manual`：用户直接输入。
- `ocr`：OCR 识别设备采集屏幕后回填并采用。
- `device`：设备采集数据或复测记录带入。
- `system`：系统自动生成，如采集时间、定位摘要。

规则：

- OCR 原值保存在 `ocr_raw_value`，最终采用值保存在 `value_text`、`value_number` 或 `value_json`。
- 用户在 App 当前页面修改 OCR 回填值时，最终提交接口一次性写入该表，并可同步生成 `coffee_ocr_correction` 记录。
- 退回后重新提交新增版本，不覆盖上一版本字段值。

### coffee_ocr_result

字段：id、photo_id、provider、status、raw_response_id、structured_json、confidence、started_at、finished_at、error_code、error_message。  
关系：一对多修正记录。

### coffee_ocr_correction

字段：id、ocr_result_id、field_name、raw_value、corrected_value、reason、version、corrected_by、corrected_at。  
规则：每次保存新增版本。App 提交前页面内纠正不要求单独调用保存接口；最终提交时可随 Manifest 一起落库为修正记录。

### coffee_provider_call_log

字段：id、provider_type、provider_name、request_id、target_type、target_id、status、latency_ms、request_digest、response_digest、raw_response_ref、error_code、called_at。  
规则：敏感字段脱敏。

### coffee_quality_review

字段：id、event_id、review_type、status、reviewer_id、reviewed_at、result_json、return_reason、return_items、version。  
状态：待审核、通过、退回、复核中。

### coffee_export_job

字段：id、job_code、export_type、filters_json、status、progress、file_path、file_sha256、created_by、expires_at、error_message。  
异步：Celery 处理。

## 配置表

- coffee_photo_category_config
- coffee_device_template
- coffee_quality_rule
- coffee_b_grade_rule
- coffee_provider_config
- coffee_metric_definition

配置表必须有版本字段。已被历史数据引用的版本不可原地修改。

## 状态字段枚举

采集事件：draft、pending_upload、uploading、pending_ocr、pending_correction、pending_submit、submitted、reviewing、approved、returned、resubmitted。  
地块复核：pending_review、confirmed、returned、adjusted。  
点位复核：pending_review、confirmed、returned、adjusted。  
照片：local、precheck_pass、precheck_warning、precheck_blocked、uploaded、review_pending、approved、returned、voided。  
OCR：pending、queued、running、success、failed、timeout、manual。  
导出：queued、running、success、failed、expired、cancelled。

## 单条详情页聚合关系

Web 单条数据详情页以 `coffee_collection_event.event_id` 为入口：

```text
coffee_collection_event
  -> coffee_task
  -> coffee_plot
  -> coffee_point
  -> coffee_event_field_value
  -> coffee_photo_asset
      -> coffee_ocr_result
      -> coffee_ocr_correction
  -> coffee_measurement_record
  -> coffee_quality_review
  -> coffee_provider_call_log
```

页面默认展示 `coffee_event_field_value` 中最终采用值，同时提供入口查看 OCR 原始值、人工纠正记录、原图、水印图和 Provider 调用日志。
