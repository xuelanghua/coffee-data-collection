# 普洱咖啡数据采集系统三份核心文档关系与使用说明

本文说明《工作任务书》《快速开发使用说明》《快速开发提示词》三份文件之间的关系，以及在实际项目中应该如何使用。

## 1. 三份文件的关系

三份文件分别解决三个问题：

```text
《工作任务书》
= 做什么、为什么做、做到什么程度

《快速开发使用说明》
= 按什么流程做、每个阶段怎么推进

《快速开发提示词》
= 直接复制给 Codex，让 AI 开始执行
```

最简单的记法：

```text
任务书：定方向
使用说明：定流程
提示词：启动 Codex
```

## 2. 《工作任务书》

《工作任务书》是项目总合同，也是后续开发、验收和交付的最高依据。

对应文件：

```text
普洱咖啡数据采集系统开发任务书-UAIDF重写版.md
```

它主要回答：

- 项目为什么要做。
- 项目要做什么。
- 一期完整交付范围是什么。
- P0/P1 分别是什么。
- 哪些内容明确不做。
- 为什么使用 `django-vue3-admin`。
- 为什么 App 优先。
- 为什么移动端使用 UniApp。
- G0-G6 门禁分别确认什么。
- 验收状态和证据规则是什么。

适合谁看：

- 项目负责人
- 客户或业务方
- 产品经理
- 技术负责人
- 测试负责人
- Codex/AI 开发代理

什么时候使用：

- 项目开始前确认范围。
- 项目中途发生范围争议时。
- 判断某个功能是否应该做时。
- 做 G1 需求确认时。
- 做最终交付验收时。

一句话：

```text
《工作任务书》决定项目做什么。
```

## 3. 《快速开发使用说明》

《快速开发使用说明》是项目操作手册，也是团队和 Codex 按 UAIDF 推进项目的路线图。

对应文件：

```text
普洱咖啡数据采集系统-UAIDF快速开发使用说明.md
```

它主要回答：

- 项目从哪里开始。
- 为什么要从 `S0 新基座初始化` 开始。
- 每个阶段应该做什么。
- 每个门禁什么时候确认。
- G1/G2/G3/G4/G5/G6 分别卡什么。
- UI 什么时候设计。
- UI 什么时候确认。
- 什么时候可以写代码。
- App、Web、后端、OCR、Provider 怎么推进。
- 什么情况下可以标记 `BLOCKED`。

适合谁看：

- 项目负责人
- 产品/业务分析人员
- UI/体验负责人
- 后端开发
- Web 开发
- App 开发
- 测试/质量负责人
- DevOps/运维
- Codex/AI 开发代理

什么时候使用：

- 每天安排开发任务时。
- 新成员加入项目时。
- 不知道下一步该做什么时。
- 阶段切换时。
- Codex 需要恢复上下文时。
- 判断是否能进入开发时。

一句话：

```text
《快速开发使用说明》决定项目怎么做。
```

## 4. 《快速开发提示词》

《快速开发提示词》是给 Codex 使用的启动指令。

对应文件：

```text
普洱咖啡数据采集系统-Codex快速开始提示词.md
```

它主要回答：

- Codex 启动后先读哪些文件。
- Codex 如何判断当前阶段。
- Codex 如何判断门禁是否确认。
- G1 未确认时应该做什么。
- G2 未确认时是否允许写代码。
- G2 已确认后如何选择开发任务。
- 如何处理 `PASS`、`FAIL`、`BLOCKED`、`NOT_VERIFIED`。
- 如何区分 Mock 证据和真实服务证据。
- 如何避免跳过 UAIDF 门禁。

适合谁用：

- 你自己
- 项目负责人
- 技术负责人
- 任何需要启动 Codex 的团队成员

什么时候使用：

- 新开 Codex 会话时。
- Codex 上下文断了，需要恢复时。
- 想让 Codex 判断项目当前阶段时。
- 想让 Codex 开始设计 UI 时。
- 想让 Codex 进入开发时。
- 想让 Codex 做测试、验收或报告时。

一句话：

```text
《快速开发提示词》负责启动 Codex 干活。
```

## 5. 推荐使用顺序

### 5.1 项目刚开始

推荐顺序：

```text
1. 先读《工作任务书》
2. 确认项目范围、目标、P0/P1 和非目标
3. 读《快速开发使用说明》
4. 明确当前应从 S0/S1/G1 开始
5. 复制《快速开发提示词》给 Codex
6. 让 Codex 判断当前阶段和门禁
7. 让 Codex 进入 S2，先做 UI 和系统设计
```

注意：

```text
G2 未确认前，不要让 Codex 写业务代码。
```

### 5.2 UI 设计阶段

推荐顺序：

```text
1. 用《快速开发提示词》启动 Codex
2. Codex 读取《工作任务书》和《快速开发使用说明》
3. Codex 判断 G1 是否确认
4. G1 已确认后，Codex 进入 S2
5. Codex 输出 App 和 Web 全部 UI 设计
6. 你确认页面、字段、按钮、权限、状态和异常流程
7. 确认通过后，进入 G2
```

注意：

```text
UI 是系统设计、用户确认、确认后开发。
```

### 5.3 开发阶段

推荐顺序：

```text
1. 确认 G2 已通过
2. 读《快速开发使用说明》中的 S3 开发顺序
3. 用《快速开发提示词》启动 Codex
4. 让 Codex 优先开发 App 采集闭环
5. Codex 按 TDD 实现最小 P0 任务
6. Codex 运行测试并更新验收证据
```

App 第一条闭环优先：

```text
登录
  -> 查看任务
  -> 选择地块/点位
  -> 创建采集事件
  -> 拍照
  -> 保存本地草稿
  -> 上传队列
  -> OCR 识别
  -> 人工校正
  -> 提交
  -> Web 审核
```

### 5.4 中途恢复项目

推荐顺序：

```text
1. 打开《快速开发使用说明》
2. 复制《快速开发提示词》给 Codex
3. Codex 读取 state、acceptance、runbook 和 last_report
4. Codex 判断当前处于 S0-S6 哪个阶段
5. Codex 判断 G0-G6 哪些已确认
6. Codex 输出下一步建议
```

不要直接说“继续开发”，而应该让 Codex 先判断：

```text
当前阶段是什么？
哪些门禁已经确认？
哪些验收项是 PASS？
哪些是 BLOCKED 或 NOT_VERIFIED？
本轮是否允许写代码？
```

### 5.5 真实服务和真机验收阶段

推荐顺序：

```text
1. 确认 G4 是否通过
2. 检查真实 Provider 配置是否齐全
3. 检查 Android/iOS 真机是否具备
4. 检查真实设备图片样本是否齐全
5. 运行真实联调
6. 记录真实服务证据和真机证据
7. 缺失条件的项目标记 BLOCKED
```

注意：

```text
Mock 通过不等于真实服务通过。
没有真实密钥、真机或真实样本时，不能写 PASS。
```

## 6. 三份文件如何配合 Codex

### 6.1 给 Codex 的正确启动方式

不要只说：

```text
继续开发
```

推荐使用：

```text
请读取《工作任务书》《快速开发使用说明》和 automation/state.json、automation/acceptance.yaml、automation/runbook.md、last_report。
先判断当前处于 S0-S6 哪个阶段，G0-G6 哪些门禁已确认。
如果 G1 未确认，先输出 G1 确认清单。
如果 G1 已确认但 G2 未确认，进入 S2，只输出 App 和 Web UI 设计，不写业务代码。
如果 G2 已确认，再选择 App 优先闭环中的最小 P0 任务开始开发。
```

更简单的方法：

```text
直接复制《快速开发提示词》全文给 Codex。
```

### 6.2 Codex 执行时的依据顺序

如果三个文件之间出现理解冲突，应按以下优先级判断：

```text
1. 用户当前明确指令
2. 《工作任务书》
3. 《快速开发使用说明》
4. 《快速开发提示词》
5. 旧项目资料和历史报告
```

旧项目资料只能作为参考，不能覆盖新版任务书。

## 7. 文件放置建议

建议把三份文件放在同一项目目录中：

```text
Coffe Data Collection/
  普洱咖啡数据采集系统开发任务书-UAIDF重写版.md
  普洱咖啡数据采集系统-UAIDF快速开发使用说明.md
  普洱咖啡数据采集系统-Codex快速开始提示词.md
  普洱咖啡数据采集系统-三份核心文档关系与使用说明.md
```

进入正式项目后，也可以复制到：

```text
docs/tasks/
docs/runbooks/
docs/prompts/
```
