# 普洱咖啡数据采集系统开发任务书

版本：G1 初版  
日期：2026-06-15  
基线：django-vue3-admin（https://gitee.com/huge-dream/django-vue3-admin）

## 1. 建设目标

在不破坏上游权限、菜单、日志、Celery 和 Web 风格的前提下，建设 UniApp 现场采集端、Django 服务端、Vue 管理端、PaddleOCR 服务及完整开发/测试环境，实现咖啡数据从现场采集到质检、标注、统计和数据集导出的闭环。

## 2. 交付范围

### P0 必须交付

- App/Web 共用用户、组织、角色和权限；手机号 + 密码登录。
- 先编号后采集、四级主键、定位、边界圈选、采样点和面积复核。
- 分类拍照、水印、不可变原图、metadata、图片预检、离线草稿、分片续传和幂等。
- 设备测量、异常复测、PaddleOCR、人工修正、OCR 留存。
- 图片和数据包质检、退回复核、B 级数量规则。
- Web 数据、图片、OCR、质检、标注、配置、统计、绩效和导出。
- MySQL 8、Redis、Celery Worker/Beat、PaddleOCR、健康检查和持久化 Compose。
- 自动测试、安全检查、真实服务配置门禁和交付文档。

### P1 必须交付但可后置到 S3 后段

- 人工框选和标签版本、统计口径中心、完整数据包离线浏览索引。
- 高德、聚合天气、OBS、华为 OCR 的配置、Mock、连接测试入口。
- 腾讯/百度地图 Provider 契约、启停、配置和可替换架构。

### 明确不承诺

首版不承诺自动识别病虫害、咖啡品种、目标检测框或分割掩码；不承诺腾讯/百度地图完整真实验收；不承诺未获得真实设备样本时的 OCR 通用高准确率。

## 3. 推荐实施方案

采用“上游框架内领域模块 + 独立 UniApp + 独立 PaddleOCR 服务 + Provider 适配层”：

- `backend/coffee/` 承载领域模型、API、权限、任务和导出。
- `web/src/views/coffee/` 与 `web/src/api/coffee/` 承载管理端。
- `coffee-collector-app/` 承载 iOS/Android UniApp、本地数据库和上传队列。
- `services/paddleocr/` 承载 OCR HTTP 服务、设备模板和预处理。
- Provider 接口隔离地图、天气、OCR、存储厂商。

该方案复用上游成熟能力，同时避免把外部厂商逻辑侵入业务模型。

## 4. 阶段任务

### S2 UI/UX 与系统设计

1. 固化领域边界、数据模型、不可变与版本策略。
2. 定义 API 契约、权限矩阵、Provider 契约和错误模型。
3. 生成 App/Web 关键页面原型说明和浏览器辅助展示。
4. 定义地图坐标系、面积计算、OCR 模板、图片命名、水印、导出和测试方案。
5. 输出设计文档并进入 G2。

完成条件：主控提示词列出的全部 S2 文档存在，设计确认清单无未披露冲突。

### S3 连续自动开发

1. 建立模型、迁移、字典和菜单初始化。
2. 实现认证、权限、核心采集、图片上传、Provider、OCR、质检、标注、统计和导出 API。
3. 实现 Web 全部业务菜单、页面和配置页。
4. 实现 UniApp 页面、本地数据库、地图、相机、水印、OCR、离线和上传队列。
5. 实现 PaddleOCR 服务和设备模板。
6. 升级 Docker Compose 与安全配置模板。

完成条件：功能无占位按钮和空接口，各项目可构建。

### S4 本地自动验证与修复

1. 静态检查、单元测试、权限测试、集成测试、E2E 和安全检查。
2. 使用 Mock Provider 验证地图、天气、OCR 和 OBS 契约。
3. 验证图片、分片续传、数据包完整性、导出目录、Manifest 和 Hash。
4. 自动修复失败并更新证据。
5. 输出 G3 配置清单并暂停。

完成条件：本地质量门禁全部通过，或仅存在清晰披露的外部阻塞。

### S5-S6 真实联调与交付

配置确认后执行高德、聚合天气、OBS、启用的华为 OCR 和真实 PaddleOCR 样本测试；支持 iOS/Android 真机验收；完成回归、安全审查、部署和最终结论。

## 6. 质量与证据规则

- 每个需求必须映射实现位置、自动/人工测试、证据和验收状态。
- Mock 仅证明契约；真实 API、OCR 真实样本和真机能力单独验收。
- 所有 API 权限和数据权限必须有正向与越权测试。
- 原始数据、原图和 OCR 原始响应不可覆盖。
- 测试失败先保存证据、补失败测试、修复并回归。

## 7. 主要风险与控制

| 风险 | 控制 |
|---|---|
| 上游版本老旧 | S2 制定兼容升级路径，业务开发前加基线保护测试 |
| GET 接口默认权限不足 | 业务 API 显式权限和数据过滤，越权测试覆盖 |
| 离线/上传导致重复或丢失 | 本地不可变记录、幂等键、SHA-256、Manifest、续传测试 |
| OCR 精度不稳定 | 设备模板、置信度、人工修正、真实样本报告 |
| 地图坐标混用 | Provider 契约显式坐标系，转换与面积测试 |
| 密钥泄露 | 环境变量/加密存储、脱敏、审计、轮换说明 |
| 大规模导出阻塞服务 | Celery 异步、进度、权限、过期清理和限额 |
