# 普洱咖啡项目新建仓库与多机同步说明书

## 1. 目标

本文档解决 3 件事：

1. 把当前混合了自动开发模板内容的仓库，拆成一个更干净的新项目。
2. 把新项目放到 GitHub 私有仓库中管理源码。
3. 让你的 Mac mini 和 MacBook Air 在 Codex 中协同编辑同一个项目。

本文档默认你希望：

- 保留当前已经开发完成的业务源码和运行配置
- 不把本地密钥、虚拟环境、依赖缓存、自动化中间产物一并搬走
- 后续以 GitHub 作为两台电脑之间的同步中心

## 2. 当前仓库里有哪些内容

当前仓库大致可以分成 4 类：

### 2.1 建议保留到新项目的业务源码

- `dvadmin-backend/`
- `dvadmin-ui/`
- `services/`
- `coffee-collector-app/`
- `scripts/`
- `docker-compose.yml`
- `docker_env/`
- `LICENSE`

这些属于项目实际可运行的核心部分。

### 2.2 视情况保留的项目文档

- `docs/`
- `README.md`
- `本地运行使用说明.md`

如果你希望把设计文档、分析文档、原型图也纳入正式项目，可以保留。

如果你只想保留一个纯净的工程仓库，也可以先只留运行文档，再逐步挑选 `docs/` 内容。

### 2.3 建议不要直接搬到新项目的自动化过程内容

- `automation/`
- `reports/`
- `.superpowers/`
- `AGENTS.md`

这些更像是本次自动开发过程的治理、验收、过程记录和 Codex 规则痕迹。

如果你想保留研发过程证据，可以单独建一个 `project-governance` 或 `delivery-records` 仓库归档。

### 2.4 明确不要搬入 Git 的本地文件

- `.env`
- `dvadmin-backend/conf/env.py`
- `dvadmin-backend/.venv/`
- `dvadmin-ui/node_modules/`
- `dvadmin-ui/dist/`
- `dvadmin-backend/media/`
- `dvadmin-backend/logs/`
- `.DS_Store`
- `.vscode/`

这些要么是密钥，要么是本地环境产物，要么是可重建文件。

## 4. 在本机创建新项目目录

### 4.1 新建空目录

在你希望存放正式项目的目录执行：

```bash
mkdir -p ~/Documents/puer-coffee-collection
```

### 4.2 从旧项目复制正式内容

假设当前旧项目目录是：

```bash
/Users/xuelang/Documents/软件开发自动化框架
```

建议逐项复制，而不是整仓库直接搬运：

```bash
cd /Users/xuelang/Documents/软件开发自动化框架

cp -R dvadmin-backend ~/Documents/puer-coffee-collection/
cp -R dvadmin-ui ~/Documents/puer-coffee-collection/
cp -R services ~/Documents/puer-coffee-collection/
cp -R coffee-collector-app ~/Documents/puer-coffee-collection/
cp -R scripts ~/Documents/puer-coffee-collection/
cp -R docker_env ~/Documents/puer-coffee-collection/
cp -R docs ~/Documents/puer-coffee-collection/

cp docker-compose.yml ~/Documents/puer-coffee-collection/
cp .env.example ~/Documents/puer-coffee-collection/
cp README.md ~/Documents/puer-coffee-collection/
cp 本地运行使用说明.md ~/Documents/puer-coffee-collection/
cp LICENSE ~/Documents/puer-coffee-collection/
```

说明：

- 这里故意没有复制 `.git/`、`.env`、`.venv`、`node_modules`、`automation/`、`reports/`。
- 这样你得到的是一个“业务内容为主”的新项目目录。

## 5. 迁移后先清理本地垃圾文件

进入新项目目录：

```bash
cd ~/Documents/puer-coffee-collection
```

建议先删除不该进仓库的内容：

```bash
find . -name ".DS_Store" -delete
```

## 7. 创建 GitHub 私有仓库

### 7.1 在 GitHub 创建仓库

在 GitHub 网页上新建一个私有仓库，例如：

```text
puer-coffee-collection
```

建议：

- 选择 `Private`
- 不要勾选自动生成 README、`.gitignore`、License

这样可以避免和本地内容冲突。

### 7.2 初始化本地 Git

在新项目目录执行：

```bash
cd ~/Documents/puer-coffee-collection
git init
git checkout -b main
```

### 7.3 首次提交

```bash
git add .
git status --short --ignored .env dvadmin-backend/conf/env.py dvadmin-backend/.venv dvadmin-ui/node_modules
git commit -m "feat: initialize puer coffee collection project"
```

在提交前，你应该确认：

- `.env` 没有进入暂存区
- `dvadmin-backend/conf/env.py` 没有进入暂存区
- `node_modules`、`.venv` 没有进入暂存区

### 7.4 绑定 GitHub 远端

SSH 方式示例：

```bash
git remote add origin git@github.com:你的账号/puer-coffee-collection.git
git push -u origin main
```

HTTPS 方式示例：

```bash
git remote add origin https://github.com/你的账号/puer-coffee-collection.git
git push -u origin main
```

推荐使用 SSH，长期更省事。

## 8. 在另一台电脑同步

### 8.1 克隆仓库

在 MacBook Air 上执行：

```bash
cd ~/Documents
git clone git@github.com:你的账号/puer-coffee-collection.git
cd puer-coffee-collection
```

### 8.2 补本地运行文件

新电脑需要自己补这些文件：

```bash
cp .env.example .env
cp dvadmin-backend/conf/env.example.py dvadmin-backend/conf/env.py
```

说明：

- `.env` 和 `conf/env.py` 不走 Git，同步时必须在每台电脑单独配置。
- 如果两台机器配置不同，不要强行做成一样，按本机实际路径和端口填写。

### 8.3 安装依赖

```bash
cd dvadmin-backend
python3 -m venv .venv
.venv/bin/pip install -r requirements-mysql.txt

cd ../dvadmin-ui
npm install
```

如果还要运行 App 或 OCR，也分别补齐依赖。

## 9. 两台 Mac 的推荐协作方式

推荐工作流：

### 9.1 在一台电脑开始工作

```bash
git pull
```

开发、测试、修改后：

```bash
git add .
git commit -m "fix: adjust login captcha and local cors"
git push
```

### 9.2 换到另一台电脑继续

```bash
git pull
```

继续开发后再次：

```bash
git add .
git commit -m "feat: update local run docs"
git push
```

### 9.3 最重要的习惯

- 开工前 `git pull`
- 暂停前 `git commit` + `git push`
- 不要两台电脑长时间同时修改同一个文件

这三条能避免 90% 的同步混乱。

## 10. 在 Codex 中如何管理同一个项目

Codex 不会自动把两台电脑的文件夹实时同步。

Codex 的正确协作方式是：

- Mac mini 上打开 `~/Documents/puer-coffee-collection`
- MacBook Air 上也打开 `~/Documents/puer-coffee-collection`
- 两边通过 GitHub 同步

也就是说：

```text
Codex <-> 本机工作目录 <-> Git commit/push/pull <-> GitHub <-> 另一台电脑工作目录 <-> Codex
```

Codex 管的是“当前这台电脑上的本地目录”，不是一个云端共享文件夹。

## 11. 如何避免把自动开发模板内容继续带入新仓库

建议用下面这个原则判断：

### 11.1 该保留的内容

判断标准：

- 直接参与系统运行
- 直接参与构建、测试、部署
- 是业务文档或架构文档

### 11.2 不建议保留的内容

判断标准：

- 只是本次自动开发过程中的中间治理产物
- 只服务于 Codex 执行过程，不服务于业务运行
- 只记录验收过程，而不是项目本体

如果你想把这些资料留档，更好的做法是：

- 单独建一个“交付归档仓库”
- 或保留在旧仓库中，仅把新仓库作为正式源码仓库

## 12. 数据库如何在两台电脑之间迁移

Git 只同步代码，不同步 MySQL 数据。

如果你希望另一台电脑也有相同测试数据，可以导出 SQL：

```bash
mysqldump -u root -p coffee_collection > coffee_collection.sql
```

把 SQL 文件拷到另一台电脑后导入：

```bash
mysql -u root -p coffee_collection < coffee_collection.sql
```

注意：

- 不建议把真实业务数据直接放进 Git
- 测试数据可以单独作为本地迁移包处理

## 13. 推荐的实际落地方案

如果你想尽量省事，我建议直接这样做：

1. 新建 `~/Documents/puer-coffee-collection`
2. 只复制业务源码、运行配置示例、正式文档
3. 不复制 `automation/`、`reports/`、`.superpowers/`
4. 初始化 Git
5. 推到 GitHub 私有仓库
6. MacBook Air 上 clone
7. 两台电脑都各自配置 `.env`、MySQL、Python venv、npm 依赖
8. 后续只通过 GitHub 同步

这是当前最稳、最清晰、后续维护成本最低的方案。
